# Scheduled refresh health

`npm run refresh` guards each stage in the existing order:
trend → events → adult → today-internet → thumbnail-repair → matome.
Standalone collector commands keep their existing behavior; the cross-stage guard
runs through `scripts/refresh-data.mjs`.

## Preservation

Before each stage, the runner snapshots that stage's generated files, including
home-news pagination. On an exception, missing/invalid JSON, broken pagination,
regressing/invalid timestamps, or a catastrophic count collapse, it restores the
whole previous group (including removed pages and removal of newly created pages).
A complete, usable previous group permits later stages to run and publishes a
warning. Without that baseline, the refresh fails and later stages do not run.
A successful earlier stage is not rolled back by a later independent failure.

Existing RSS/event full-failure fallbacks remain intact. A no-write fallback is
reported as retained, and previous timestamps are never changed to the attempt
time. News images missing from a new candidate are recovered through the existing
exact-ID + article-URL thumbnail helper; newly retrieved usable images remain
preferred. Final thumbnail repair and home-news consumer synchronization keep
their original position and implementation.

The rollback guard covers caught failures, not abrupt process/runner termination.
GitHub Actions does not commit or deploy data after a fatal/terminated refresh.

## Conservative thresholds

- Stale data: generated/fetched timestamp older than 3 hours (six scheduled runs)
- Count decline: at least 20 previous entries, compared with a baseline no more
  than 24 hours old; a decline of 50% warns and 90% rejects the candidate
- RSS counts: raw fetched count is also compared, because the capped current list
  and retained archive can hide a major fetch decline. This comparison becomes
  available after the first snapshot containing `collectionSummary`
- Image coverage: at least 20 comparable entries in both snapshots and a decrease
  of at least 25 percentage points warns. Missing exact-article images are
  restored first, with a separate recovery diagnostic; a change in topic/source
  mix alone never rejects fresh stories
- Timestamp: missing/invalid values, times more than one hour into the future,
  and backwards generation times reject the candidate

Event count and thumbnail comparisons use only entries still in the collector's
existing Japan-time collection window. A mass end-date expiry is therefore not
misdiagnosed as a collector failure. Optional small sections and pagination tail
sizes can legitimately shrink. Empty current adult collection is invalid, while
an empty event collection can be valid after expiry.

These are operational warnings, not claims about article truth or successful
image delivery in every browser. Image coverage uses the existing URL sanitizer;
it does not add remote image requests or a paid monitoring service.

## Status and Actions

`data/refresh-status.json` (schemaVersion 1) is generated by the runner, not edited
by hand. Its `checkedAt` is the refresh attempt time. `datasets[filename]` exposes
`generatedAt`, `itemCount`, `thumbnailCount`, `thumbnailCoverage` (0–1), `stale`,
`retained`, and structured `issues`. Array-shaped adult feeds use their newest
item `fetchedAt`/`updatedAt`; this is not a new envelope timestamp. Stage results
are `ok`, `retained`, or `failed`; overall status is `ok`, `warning`, or `failed`.

Warnings are emitted as Actions annotations and an Actions step summary. The
workflow saves the report as an artifact even on fatal failure. A warning with
usable fallback data returns success so the normal JSON commit/deploy publishes
the report and retained datasets. Fatal first-run/invalid-baseline failures remain
nonzero and are not committed or deployed.

Classic home and all-news pages read the report without blocking normal loading.
They show a notice only for stale, retained, or failed data, with the original
retrieval timestamp in JST. The browser recalculates age from `generatedAt`, never
`checkedAt`, and checks again when the tab becomes visible. A missing report before
the first guarded run does not break the pages. No existing article timestamp,
category, ranking, or pagination schema is repurposed.

## Verification

Run `node --test tests/*.test.mjs`, `node --check` for changed JavaScript, and
`git diff --check`. `tests/refresh-health.test.mjs` covers partial writes, deleted
and new pages, caught exceptions, no-baseline failure, source-count decline,
image identity recovery, stale timestamps, JST event expiry, and Actions output.
`tests/refresh-status-ui.test.mjs` covers notice conditions and missing-report
recovery. Tests use deterministic fixtures and do not depend on live publishers.
